# РААААРРРАГОЧІ — повна інструкція розгортання
Версія комплекту: 10.11.2026
Вихідний коміт: 063376f41bd39a4c7915641696e5aacdb501e468 (PR #126, без Dynamic Island і PushWard).

## Що в комплекті
Це повний вихідний код гри з усіма ресурсами та тестами. Гра запускається як Telegram Mini App на Cloudflare Workers. Мобільний компаньйон — PWA, а не окремий нативний застосунок. Доступні пети, вікові стадії, кімната, одяг, догляд, характер, ігри, альбом, економіка й соціальна пісочниця. Telegram-нагадування та Web Push залишено.

**Важливо:** архів не переносить існуючу базу збережень, гравців, монети чи підписки на сповіщення. Новий Worker створить нове сховище PETS. Не копіюйте старий токен бота, старий код прив'язки або VAPID-ключ. Не потрібно створювати D1, KV, Cron Trigger або окремий сервер: стан і будильники зберігаються у SQLite-backed Durable Objects. Безкоштовні тарифи GitHub і Cloudflare достатні для невеликого проєкту в межах їхніх лімітів; стежте за використанням, не підключайте платні послуги без потреби.

## 1. Підготуйте інструменти
1. Зареєструйтеся на https://github.com/ і https://dash.cloudflare.com/ або увійдіть у свої нові акаунти.
2. Встановіть Node.js 22 LTS (https://nodejs.org/) та Git (https://git-scm.com/). Для Windows зручно використовувати PowerShell або термінал VS Code.
3. Розпакуйте ZIP. Відкрийте папку, в якій поруч є package.json, wrangler.jsonc, public/ та src/. Якщо ZIP має зовнішню папку з назвою репозиторію, перейдіть всередину неї.
4. У терміналі виконайте:
```sh
node --version
npm --version
npm ci
npm run build
npm test
```
Очікування: Node 22+, збірка без помилок, усі тести зелені. Для повної браузерної перевірки:
```sh
npx playwright install chromium
npm run test:graphic-qa
node scripts/companion-browser-qa.mjs
```
На Linux може знадобитися `npx playwright install --with-deps chromium`. Node_modules та згенеровані тимчасові файли не завантажуйте в GitHub.

## 2. Створіть свого Telegram-бота
1. Відкрийте офіційного @BotFather у Telegram: https://t.me/BotFather
2. Надішліть /newbot.
3. Вкажіть назву, наприклад РААААРРРАГОЧІ, та унікальний username, що закінчується на bot (наприклад MyPixelPetsBot).
4. BotFather видасть токен. Збережіть його у менеджері паролів. Це BOT_TOKEN, а не ім'я бота. Не додавайте його у репозиторій, HTML, скриншоти, .env у ZIP або повідомлення чату.
5. Відкрийте чат зі своїм новим ботом і натисніть Start. Бот не має обробника /start або окремого webhook у цій збірці: відсутність текстової відповіді не означає несправність Mini App. Запуск гри налаштуємо після деплою.

## 3. Змініть ім'я Cloudflare Worker
Відкрийте wrangler.jsonc. Змініть лише поле name, наприклад:
```json
"name": "my-pixel-pets"
```
Використовуйте латиницю, цифри та дефіси. Залиште main = src/worker.js, assets.directory = ./public, binding ASSETS, run_worker_first = true, PETS / PetRoom та migrations (v1, new_sqlite_classes). Збережіть compatibility_date, build і keep_vars. Не змінюйте назву класу або міграції для нового проєкту. Worker з такою назвою не повинен уже існувати в цільовому акаунті, якщо вам потрібна абсолютно нова копія.

## 4. Розгорніть Worker (найнадійніший спосіб: Wrangler)
У папці проєкту:
```sh
npx wrangler login
npx wrangler whoami
npx wrangler deploy
```
У браузері підтвердьте авторизацію саме в НОВОМУ акаунті Cloudflare. Перевірте акаунт у whoami. Wrangler збере клієнт, завантажить статичні файли та створить Durable Object namespace через міграцію. Якщо запропонує зареєструвати workers.dev subdomain — оберіть безкоштовну назву. Наприкінці скопіюйте фактичну HTTPS-адресу, наприклад https://my-pixel-pets.my-account.workers.dev. Не використовуйте старий домен іншого проєкту.

Додайте секрет нового бота:
```sh
npx wrangler secret put BOT_TOKEN
```
Вставте токен у прихований інтерактивний запит і натисніть Enter. Не додавайте токен до команди як аргумент. Повторно перевірте deployment у Cloudflare. За потреби виконайте `npx wrangler deploy`. Перевірка: відкрийте ВАШ_HTTPS_URL/api/health — має бути {"ok":true}. Відкрийте корінь ВАШ_HTTPS_URL — має завантажитися гра. У звичайному браузері це локальне демо; серверне збереження перевіряється лише в Telegram.

Якщо Wrangler пропонує вибір акаунта — виберіть свій новий. Для кількох акаунтів можна вказати account_id у wrangler.jsonc після отримання ID з Dashboard; він не є секретом. Не використовуйте чужий Account ID.

## 5. Підключіть GitHub (автодеплой після змін)
1. На GitHub створіть НОВИЙ порожній репозиторій, краще Private, без README/ліцензії/.gitignore, бо вони вже є в комплекті. Не використовуйте оригінальний репозиторій як місце для нових секретів.
2. У розпакованій папці (не у старому клоні з чужим remote):
```sh
git init
git add .
git commit -m "Initial tamagotchi deployment"
git branch -M main
git remote add origin https://github.com/ВАШ_USERNAME/ВАШ_REPO.git
git push -u origin main
```
Якщо Git попросить ім'я та email, налаштуйте git config user.name і user.email, використовуючи свої дані. Авторизуйтесь через GitHub Credential Manager або GitHub CLI; не вставляйте токен у URL.
3. У Cloudflare відкрийте Workers & Pages → ваш Worker → Settings → Builds / Git integration (або створення Worker з Git repository, якщо ще не робили CLI-деплой).
4. Підключіть GitHub і дозвольте доступ лише до нового репозиторію. Виберіть main як production branch. Root directory — корінь репозиторію; Build command — порожній, якщо Wrangler сам запускає build з wrangler.jsonc; Deploy command — npx wrangler deploy. Якщо потрібен install command: npm ci. Не підключайте Pages замість Workers: серверний PetRoom потребує Worker.
5. Worker name у Cloudflare має збігатися з wrangler.jsonc. Якщо Dashboard створює інший Worker, поверніться до кроку 3 та узгодьте назву перед deployment. Не створюйте дублікати, якщо вже є потрібний Worker.
6. У Settings → Variables and Secrets перевірте runtime Secret BOT_TOKEN (не build variable). Не додавайте токен до GitHub. За потреби Add → Secret, Save/Deploy. Повторний push у main має запускати деплой. GitHub Actions у комплекті запускає тести, а Cloudflare Git integration — публікацію; це різні процеси.
7. Перевірте, що в Deployments останній деплой успішний і фактичний URL відкривається. Якщо інтерфейс Cloudflare змінився, CLI-спосіб з кроку 4 залишається альтернативою.

## 6. Прив'яжіть Telegram Mini App
1. @BotFather → /mybots → виберіть СВОГО нового бота → Bot Settings → Configure Mini App / Main App. Увімкніть Main Mini App і вкажіть фактичний HTTPS URL нового Worker (корінь, не /companion.html, не GitHub).
2. Якщо меню пропонує налаштування через /newapp або /editapp, створіть/відредагуйте Mini App для цього бота з тією самою HTTPS-адресою. Задайте назву та short name, якщо запитає. За потреби завантажте іконку з public/companion-icon.png.
3. Налаштуйте кнопку меню: @BotFather → /setmenubutton → новий бот → HTTPS URL Worker → назва «🐾 Грати» (або через Bot Settings → Menu Button). 
4. Відкрийте чат зі своїм ботом. Натисніть Start, потім кнопку «Грати» / Open App. Не використовуйте для цього звичайне посилання в Safari.
5. Створіть тестового пета. Погодуйте, закрийте Mini App, відкрийте знову. Ім'я, вік, монети та характеристики мають зберегтися. Перевірте з другого Telegram-акаунта: його пет має бути окремим. Помилка 401 означає, що initData не підписана токеном цього бота або сесія застаріла; перевірте BOT_TOKEN і відкрийте заново з бота.

## 7. Власник та приватна тестова кімната (необов'язково)
Для власницьких функцій (приватна лабораторія, права овнера в економіці) потрібен числовий Telegram user ID саме вашого акаунта, не ID бота і не username. Якщо знаєте свій ID, додайте його як runtime variable OWNER_TELEGRAM_ID у Worker → Settings → Variables and Secrets або:
```sh
npx wrangler secret put OWNER_TELEGRAM_ID
```
Вставте лише цифри. Якщо не знаєте ID, відкрийте новий бот, надішліть йому повідомлення та використайте Telegram Bot API getUpdates у локальному скрипті з прихованим введенням токена (не передавайте токен стороннім сервісам). У відповіді знайдіть message.from.id. Якщо у бота вже є webhook, getUpdates може бути недоступним; використовуйте свій відомий ID. Необов'язково для звичайної гри. /lab навмисно недоступна без перевіреної Telegram-сесії власника; просте відкриття URL у браузері повертає 403.

## 8. Перевірте сповіщення
### Telegram
У чаті з новим ботом натисніть Start. У грі знайдіть нагадування (♧ або відповідний пункт налаштувань), дозвольте боту надсилати повідомлення. За замовчуванням вони вимкнені. При показнику нижче 70% планується нагадування через 10–40 хв; повторна перевірка стану перед відправкою, не частіше одного за 3 години, до 3 на добу на канал, тиша 23:00–09:00. Закрийте гру й перевірте доставку в дозволений час. Не потрібно налаштовувати Cron чи Telegram webhook. При блокуванні бота або помилці 403 нагадування вимикаються. Тимчасовий збій мережі може пропустити окреме нагадування до наступного вікна; це відоме обмеження поточного коду.

### iPhone Web Push (iOS 16.4+)
1. У Telegram-грі натисніть «📱 Підключити віджет iPhone». Скопіюйте код прив'язки приватно.
2. У Safari відкрийте ВАШ_HTTPS_URL/companion.html.
3. Поділитися → На початковий екран → Додати. Запустіть іконку з початкового екрана.
4. Вставте новий код прив'язки. Перевірте, що бачите саме свого пета. Дії з мобільної сторінки мають зберігатися у Telegram.
5. «Увімкнути сповіщення» → дозволити → «Надіслати тест». Перевірте банер/центр сповіщень і відкриття гри після натискання. Тест можна надсилати не частіше разу на хвилину.
6. Якщо підписка застаріла — вимкніть/увімкніть сповіщення заново. Перевірте iOS Settings → Notifications, Focus/Do Not Disturb, встановлену PWA та HTTPS. Нова прив'язка відкликає попередню підписку; підтримується одна підписка на пета. Звичайний Safari tab не замінює встановлену PWA. Android Chrome також може використовувати Web Push, якщо браузер підтримує потрібні API; перевірте на пристрої.
7. VAPID-ключі генеруються сервером автоматично; не потрібен Apple Developer акаунт, PushWard або сторонній віджет. Dynamic Island відсутній. Автоматичні тести не гарантують реальну доставку на конкретний телефон: перевірка кнопкою обов'язкова.

## 9. Контрольний список перед запуском
- [ ] HTTPS URL /api/health відповідає {"ok":true}.
- [ ] Mini App відкривається саме з нового Telegram-бота.
- [ ] Пет створюється та зберігається після повторного входу.
- [ ] Два Telegram-акаунти мають різних петів.
- [ ] Їжа, догляд, сон, одяг, графіка і меню працюють.
- [ ] Telegram-нагадування ввімкнено і реально отримано хоча б одне.
- [ ] iPhone PWA синхронізована та тестове сповіщення отримано.
- [ ] Cloudflare Deployments показує актуальний успішний деплой.
- [ ] BOT_TOKEN та приватні ключі не потрапили до GitHub.
- [ ] Старий проєкт не змінено; новий Worker використовує окреме сховище.

## 10. Типові проблеми
| Симптом | Рішення |
|---|---|
| 401 / Telegram auth required | Відкрийте через нового бота, звірте runtime BOT_TOKEN; сесія дійсна до 24 годин. |
| 503 / BOT_TOKEN missing | Додайте runtime Secret, перевірте правильний Worker і redeploy. |
| Worker не збирається | Node 22+, npm ci, npm run build; перевірте wrangler.jsonc та logs. |
| Durable Object migration error | Для чистого проєкту залиште PETS, PetRoom і v1 SQLite; не видаляйте міграцію. |
| Порожній екран/404 | Перевірте URL, assets.directory ./public, збірку клієнта та worker deployment. |
| Пет не зберігається між телефонами | Переконайтеся, що входите через той самий Telegram-акаунт і той самий Worker. Звичайний браузер має локальне демо. |
| Сповіщення не приходять | Дозвіл на запис бота, тиша, поріг 70%, активний пет, підписка Web Push, тестова кнопка, налаштування iOS. |
| PushWard / Dynamic Island | Цю функцію видалено; нічого підключати не потрібно. |
| Зміни в GitHub не видно | Перевірте Cloudflare Builds/Deployments, production branch і Worker name; CI success ≠ production deploy. |

## 11. Оновлення, резервні копії, перенесення
Перед великими змінами створіть Git-тег або backup branch. Змінюйте код, виконуйте npm run build і npm test, commit/push, перевіряйте Cloudflare. Для відкату коду скористайтеся Git revert або попереднім Cloudflare deployment, не видаляйте Durable Objects. Відкат коду не повертає базу в минулий стан. Архів — резервна копія вихідного коду, не production data backup. Перенесення живих збережень до іншого акаунта Cloudflare потребує окремої контрольованої міграції/export/import із перевіркою прав; готового масового експорту в цій версії немає. Новий бот і Worker за інструкцією починають з чистого сховища. 

Офіційна документація: https://developers.cloudflare.com/workers/wrangler/ ; https://developers.cloudflare.com/durable-objects/ ; https://core.telegram.org/bots/webapps ; https://core.telegram.org/bots/api .
